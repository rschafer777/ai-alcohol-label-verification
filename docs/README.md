# LabelVerify Documentation Set

This documentation follows the controlled product path from discovery through release and preserves material changes through governed configuration management.

1. `00-governance`: change control, PROC-009/010/011/013 conformance, and lifecycle authority
2. `01-discovery`: assignment and stakeholder baseline
3. `02-intake`: complete product requirements and success measures
4. `03-baird`: Beginning Assessment Intake Requirements Document
5. `04-i2r-ae`: Ideation-to-Realization architecture and engineering design
6. `05-frd`: feature requirements and traceability
7. `06-build-instructions`: build plan, work packages, tests, and Definition of Done
8. `07-development`: implemented component and interface record
9. `08-validation`: validation protocol, results, objective evidence, and the regulatory validation record (`REGULATORY_VALIDATION.md`) that maps every applied rule to its current TTB and eCFR source
10. `09-qa-qc-uat`: QA, QC, UAT, and defect-loop controls
11. `10-release`: release contents, deployment, and operational handoff
12. `11-federal-authorization-readiness`: federal authorization starter package

The source of truth for machine-enforced limits and rules is in `contracts/`. Product documentation explains those contracts and traces them to stakeholder needs.

The current corrective authority is CR-002 in `00-governance/CHANGE_CONTROL_REGISTER.md`. Earlier implementation and validation records are retained as historical evidence and must not be presented as corrective-release exit evidence.
