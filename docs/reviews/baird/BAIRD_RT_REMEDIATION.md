# BAIRD Red-Team Remediation

**Stage:** BAIRD product and technical analysis  
**Review rounds:** Initial challenge plus sealed V1, V2, V3, and V4 rereviews  
**Remediation rule:** Every material finding remains closed only if all three reviewers return CLEAR on the same corrected snapshot.

## Corrected architecture baseline

- React, TypeScript, and Vite frontend served from the same origin as a Python 3.12 FastAPI API.
- One modular-monolith OCI image promoted by immutable digest.
- RapidOCR 3.4.2 with ONNX Runtime 1.22.1 and the exact three-file model BOM in `docs/baird/evidence/MODEL_BOM.md`.
- Reference-blind OCR candidate generation and primary selection. Expected values first enter at comparison.
- One Uvicorn HTTP process and one killable OCR child process. One OCR job runs at a time.
- One to six JPEG, PNG, or WebP files, each at most 8 MiB and 12 megapixels, with 24 MiB aggregate encoded payload, 36 megapixels cumulative source pixels, and a 5.94 megapixel working canvas.
- A process-global two-POST pre-body admission cap. Each admission reserves 50,593,792 bytes for the multipart parser copy plus the controlled request copy, totaling 101,187,584 bytes within a 128 MiB application spool quota.
- A 3.0 second total request-body deadline starts at pre-body admission and never resets with chunk activity. One owned multipart parser applies exact limits and explicitly closes partial uploads. Expiry returns 408 after cleanup and reservation release.
- The OCR worker lock has a 200 ms acquisition deadline. A separate supervisor retains artifact ownership through repeated cancellation and shutdown until actual worker termination or completion, then cleanup and capacity release occur.
- Exact model, selected-check registry, and regulatory-rules registry hashes and versions plus non-writable governed assets are required before readiness.
- One always-running Fly.io Machine in `iad`, class `shared-cpu-2x` with 2 GiB RAM, current monthly ceiling 15 USD, TCP 65535 allowed while conventional ports 53/80/443 are denied, readiness warmup, and release-time platform readback.
- Batch remains a post-core Should objective and cannot begin until every single-submission release gate passes.
